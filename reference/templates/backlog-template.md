# Backlog Template

## How to Use This

Organize your backlog into three files for clarity:
- `ideas.md` - Things to explore, not yet committed
- `in-progress.md` - Active work
- `completed.md` - Archive of finished work

---

## Ideas Format

Keep ideas lightweight - just enough to remember what you were thinking:

```markdown
## High Priority
- Multi-user support - let families share one subscription
- Offline mode - download schedule for poor venue connectivity
- Push notifications - alert when team's routine time approaches

## Medium Priority  
- Export to calendar - add events to Google/Apple calendar
- Venue maps - show floor plans with stage locations
- Score tracking - record team placements across season

## Low Priority / Maybe Someday
- Social features - share photos from competitions
- Travel planning - hotel/restaurant recommendations near venues
```

---

## In-Progress Format

Track what's actively being worked on with more detail:

```markdown
## Active Features

### Feature Name
**Priority:** High  
**Brief:** briefs/feature-name.md  
**Status:** Planning | Implementation | Review  
**Started:** YYYY-MM-DD  
**Assignee:** Claude Code | Codex | Human

**Quick Status:**
- What's done
- What's next
- Any blockers

---

### Another Feature
...
```

---

## Completed Format

Archive finished work with outcome notes:

```markdown
## 2026-Q1

### Feature Name
**Completed:** YYYY-MM-DD  
**PR:** #123  
**Brief:** briefs/feature-name.md

**Outcome:**
- What shipped
- What was cut
- Impact/learnings

---
```

---

## Tips

1. **Move items between files** as they progress (ideas → in-progress → completed)
2. **Keep completed items** for historical reference and pattern recognition
3. **Link to briefs** for full context, keep backlog entries short
4. **Regular grooming** - review ideas list monthly, archive old completed items quarterly
5. **Priority is relative** - high/medium/low within each project, not universal
