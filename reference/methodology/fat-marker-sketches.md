# Fat Marker Sketches

**Purpose:** Visual sketches done with thick markers (or rough wireframes) to show the concept without committing to specifics.

---

## What are Fat Marker Sketches?

Visual representations of UI that:
- **Force you to stay high-level** - can't draw fine details with a fat marker
- **Show the concept** without committing to exact layout
- **Leave room for problem-solving** during implementation
- **Communicate structure** - where things go, relative importance

---

## When to Use

Use fat marker sketches when:
- The visual layout matters to the solution
- You need to communicate spatial relationships
- The UI structure is a key part of the design
- You want to explore multiple layout options quickly

---

## Guidelines

1. **Use rough shapes** - boxes, lines, scribbles
2. **Label components** - what is each thing?
3. **Show hierarchy** - what's most important?
4. **Avoid pixel perfection** - no exact measurements
5. **Include annotations** - notes about behavior, interactions

---

## Example Structure

```
┌─────────────────────────────────────┐
│  Page Title                         │
├─────────────────────────────────────┤
│                                     │
│  [ Big important thing ]            │
│                                     │
│  Secondary item 1                   │
│  Secondary item 2                   │
│                                     │
│  [Button]                           │
│                                     │
└─────────────────────────────────────┘

Notes:
- "Big important thing" is the primary action
- Button triggers X behavior
```

---

## Key Principles

- **Rough is good** - prevents premature optimization
- **Focus on structure** - not styling
- **Annotate behavior** - what happens when you click?
- **Multiple versions** - try different approaches quickly
- **Throwaway artifacts** - these are for thinking, not documentation
